# Daikin FTXS50KVM (Infrared)

[![Open your Home Assistant instance and open a repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=DAB-LABS&repository=daikin-ac-ftxs50kvm-ir&category=integration)

Home Assistant control for a Daikin FTXS50KVM split air conditioner, over any infrared blaster Home Assistant can already talk to. It sends the same codes the ARC433B70 handheld remote sends.

**Status: untested by others.** It has one recorded fitting, from the person who captured the codes, made on a real FTXS50KVM. Nobody else has confirmed it on their own unit yet. If you install it and it drives your air conditioner, please say so in an issue, because that is the only thing that moves it out of this state.

This is not Home Assistant's own Daikin integration. That one talks to Daikin's Wi-Fi adapters. This one is for units without Wi-Fi, controlled the way the handheld remote controls them.

---

## The device

| | |
|---|---|
| Indoor unit | Daikin FTXS50KVM |
| Remote | ARC433B70 |
| Protocol | DAIKIN216: two frames per code, 64 and 152 bits, 37.7 kHz |

Other Daikin units that ship with an ARC433B70 or ARC433B69 remote may speak the same protocol. If yours does and this works, an issue saying so is useful to everyone.

---

## What you get

**One climate entity.** Off, Cool and Heat, 18 to 30 °C in steps of one degree, five fan speeds (Low, Medium low, Medium, Medium high, High) and four swing settings (Off, Vertical, Horizontal, Both).

That is everything the codes this was built from cover. The remote has more (Auto, Dry and Fan modes, Auto and Quiet fan, timers, Powerful), and none of it was captured, so none of it is offered. This integration would rather expose less than send a code nobody recorded.

### How it works, and what it cannot know

An air conditioner remote does not send buttons. Every press sends the whole state: mode, fan, swing and temperature together. So every change you make in Home Assistant sends one complete state, looked up in a table of 520 codes captured off the real remote, one per combination, plus Off. Nothing is generated or guessed; every code that goes out is one that was recorded.

Infrared is one way. Home Assistant cannot see whether the unit changed, and it does not hear the handheld remote, so the entity shows the last state Home Assistant sent. If someone uses the handheld, the entity is out of step until the next change from Home Assistant, which sends the whole state again and puts the two back together. That is also why the entity is marked as an assumed state.

Changing fan, swing or temperature while the unit is off sends nothing; the change is kept and goes out with the next Turn on.

### Sends per change

Each change transmits once by default. That is a setting, under the integration's Configure.

The number comes from the wig: every code in it asks for one send. Because each code carries the complete state, sending it again only sets the same state again, so raising it is harmless. If changes are sometimes missed, because the blaster is far away or at an angle, raise it to two or three.

## Installing

**Through HACS.** Use the badge above, or add `https://github.com/DAB-LABS/daikin-ac-ftxs50kvm-ir` as a custom repository of type Integration, then install and restart.

**By hand.** Copy `custom_components/daikin_ftxs50kvm_ir` into your `config/custom_components/` and restart.

Then add the integration from **Settings, Devices and services, Add integration**, and pick the infrared emitter that can see the indoor unit.

You need an infrared emitter already set up in Home Assistant on the `infrared` platform. ESPHome, Broadlink and Tuya devices all work. Every code ends on a short, fixed silence, which Broadlink RM4 Pro firmware needs and which fits the 16-bit limit of Tuya and ZoSung blasters.

### Fittings

A fitting is a signed set of claims: somebody sent the codes to the real device and vouched for the ones that worked. On an air conditioner nobody presses 520 cells, so a fitting covers a fixed checklist that exercises every mode, every fan speed, every swing setting, both ends of the temperature range, and off and on.

| Fitter | GitHub | Date | Rows claimed | Signed |
|---|---|---|---:|---|
| Andre Mello | none | 2026-09-10 | 12 of 12 | key `36abf407e6b92e18` |

**12 of 12 checklist rows proven, by 0 distinct GitHub accounts of 3.** Those are different numbers and both are true. The checklist is complete and the signature verifies; the fitting names no GitHub account, so it does not count toward the account total, which counts only accounts a reader can check. A signature proves the record has not been altered since it was made. It does not prove identity, and it is not meant to.

The 12 checklist rows were each sent to the unit. The other 508 codes were not individually pressed; they are covered by the same capture and by the checks below.

### How it was checked

Nothing here was eyeballed. Before publication, by machine:

- **The table is the wig's.** The codes shipped in `lattice.json` are the wig's climate block, field for field.
- **Every state lands on the right code.** The lookup that picks a code is a copy of HAIR's own. It was run against HAIR's for 1,080 requests, every state the entity offers plus off-grid and out-of-range temperatures, and agreed on all of them. Every state you can select lands on exactly its own code, and all 520 codes can be reached.
- **Every code goes out as HAIR would send it.** All 521 codes convert to exactly the timings HAIR transmits, terminator included.
- **On the air.** On a test bench, the integration drove a Broadlink blaster and an Athom receiver listened. Every change through the checklist, plus Off, Turn on after a restart and off-grid temperatures, was heard back and decoded as exactly the code for the state asked for, checksums intact. That proves the right codes leave a real blaster. It does not prove a unit obeys them; the fitting above is the evidence for that.

## When something does not work

**Nothing responds at all.** Check the blaster can see the indoor unit. Infrared will not go round a corner, and the receiver window on a wall unit is small.

**Changes are sometimes ignored.** Raise **Sends per change** under Configure.

**The unit does something different from what Home Assistant shows.** Someone probably used the handheld remote. Make any change in Home Assistant and the whole state is sent again.

**It works on a Daikin that is not an FTXS50KVM.** Worth an issue, and genuinely useful: include the model of the indoor unit and of the remote.

**It does not work on your FTXS50KVM.** Also worth an issue. Say which blaster you use, and which settings fail.
